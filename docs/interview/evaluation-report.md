# Agent 评测报告

## 结论

已在相同的 `deepseek-v4-flash` 模型、90 秒单样本超时、同一 30 条固定样本和相同外部服务可用性下，完成 V1 与 V2 的真实执行。原始运行记录保存在被 Git 忽略的 `evals/runs/`，本报告仅保留可复核的脱敏聚合数据。

| 指标 | V1 | V2 | 变化 |
| --- | ---: | ---: | ---: |
| 样本数 | 30 | 30 | 0 |
| 完成率（`completed`） | 26.7%（8/30） | 80.0%（24/30） | +53.3 个百分点 |
| 预期角色覆盖率 | 6.7%（2/30） | 33.3%（10/30） | +26.6 个百分点 |
| 必需事实覆盖率 | 0.0% | 33.3% | +33.3 个百分点 |
| 含 URL 的回答占比 | 0.0% | 0.0% | 0 |
| 全样本平均时延 | 19.57 秒 | 24.33 秒 | +4.76 秒 |
| 成功样本平均时延 | 12.57 秒 | 19.26 秒 | +6.69 秒 |

V2 的完成率和预期角色覆盖率均有提升，但时延增加；当前不能据此声称事实正确性或引用完整性提升。自动评分仅检查样本中预设关键词、角色轨迹和回答中的 URL，不替代人工事实核验。

## 执行条件与失败边界

- 每版按网络、知识库、数据库、多 Agent、模糊/错误五类样本分别真实执行，共 30 条。
- V1 有 22 条 `EVAL_EXECUTION_FAILED`；V2 有 4 条 `EVAL_EXECUTION_FAILED` 和 2 条 `EVAL_TIMEOUT`。
- 两条 V2 超时发生在 DeepSeek thinking 兼容设置修复前，保留为真实历史结果，未重写或删除。
- 历史运行时知乎凭据未配置，MySQL 鉴权失败且 RAGFlow 尚未移除；因此当时的 URL 型引用指标为零。当前知乎已恢复 live 模式，RAGFlow 已从项目移除，历史指标不应与当前配置混用。
- 运行记录不包含密钥、连接串、绝对路径或用户上传内容。

## 尚未完成的人工环节

人工盲评尚未开展，不以自动评分补作人工评分。下一轮应由至少两位独立评审隐藏 Prompt 版本，对任务完成、事实正确、来源完整、可解释性和可用性按统一量表评分，并记录分歧处理规则。

## 固定演示任务验证

通过本地 API 连续提交、确认并轮询同一问题三次，三次均进入 `succeeded`：70.0 秒、12.3 秒、8.2 秒。每次结果均非空，并包含 demo/降级标记。该验证证明当前 DeepSeek 配置下的任务创建、计划确认、后台执行和终态快照链路可用；它不代表外部来源已恢复为实时数据。

RAGFlow 移除且知乎恢复 live 后，又完成一次公开研究 API 任务：8.2 秒进入 `succeeded`，结果标注了来源和 live 模式。该次最终回答尚未稳定包含 URL，逐条引用呈现仍是后续优化项。

## 可复现命令

模型和外部数据快照一致时，可按类别重跑；运行记录会断点续写，不能与历史结果混合后再宣称严格对比：

```powershell
.\.venv\Scripts\python.exe -m evals.runner --prompt-version v2 --case-file evals/cases/network.jsonl --output evals/runs/v2.jsonl --live --timeout-seconds 90
```
